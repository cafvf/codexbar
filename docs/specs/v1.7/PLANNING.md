# CodexBar v1.7 — Diagnose Planning Record

Status: planning concluded
Theme: Diagnose
Validated baseline: v1.6.0 — Context

The planning review approved four release pillars:

1. **Diagnose** — one typed health model rendered in CLI, JSON and UI.
2. **Isolate** — one active GUI owner per user/session.
3. **Do not block** — heavy Context and redeem I/O leave the Qt interaction path.
4. **Verify** — the headless release contract becomes reproducible CI.

The formal specification is now frozen in `PRODUCT.md`, `DECISIONS.md`,
`REQUIREMENTS.md`, `ACCEPTANCE-CRITERIA.md`, `ARCHITECTURE.md`,
`TRACEABILITY.md`, tests and phase plans.

Planning findings that require measurement are encoded as explicit evidence tasks
with a default "no change" outcome. They are not implicit implementation promises.
